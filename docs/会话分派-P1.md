## 2. 行为差异

| 会话类型 | 改之前 | 改之后 |
|---|---|---|
| 私聊 / 本地会话 | 有状态卡 + 补原文 | **不变** |

`classify()` 对不认识的 id 一律返回 `personal`——保证本地 `session-<uuid>` 会话行为与改前一致。

## 4. 实测与设计文档不一致的 4 点

> 设计文档指《记忆系统改造》的 10/12 章（写于 2026-11-17，当时未实操）。

### ① 回调参数不是 agent，是 `{ agent, source, signal }`

12 章示例：`ctx.on('agent/created', (agent) => agent?.session?.id)` → 实测拿 `null`。

正确写法：

```js
ctx.on('agent/created', ({ agent }) => {
  const sessionId = agent?.session?.id
})
```

12 章那句兜底 `agent?.session ?? agent?.agent?.session` 恰好能跑，但语义是错的（读的是 `event.agent.session`）。

### ② `agent.ctx` 的 `Object.keys()` 是空的

`agent.ctx` 是 Cordis 作用域上下文（代理），不能靠 keys 判断服务在不在；直接读
`agent.ctx.systemPrompt` / `agent.ctx.tools`。

### ③ 会话 id 多一种形状

| 来源 | 形状 | 状态 |
|---|---|---|
| 本地 DSH 会话 | `session-<uuid>` | 文档未提，已加兜底 |
| lanxi | `onebot-private-<QQ>` / `onebot-group-<群号>` | 待验 |
| msg-hub | `ch-qq-c2c-*` / `ch-qq-group-*` | 待验 |

### ④ 代码改动不会热加载

- 改 `package.json` / `cordis.patch.yml`（配置层）→ 立即生效（实测换链接当场重载）
- 改 `lib/*.js`（代码层）→ **必须重启 DSH**

排障时别把这两种混在一起判断。
