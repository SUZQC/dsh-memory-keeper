# 附件解析（QQ 文件消息 → 文本）

> 分支：`feature/group-split` · 实测环境：DSH 0.2.2-rc.3 / Node 24.21.0 / Windows · 2026-11-22

## 为什么需要

QQ 机器人的**文件消息**（另一个机器人发的 `.docx` 日报等）到达时是这样：

```json
{ "content": "", "attachments": [{ "content_type": "file", "filename": "AI日报.docx", "url": "https://..." }] }
```

`content` 是空的，正文全在附件里。如果不处理：
- 模型只看到“一条空消息”；
- 早期版本甚至会把空消息当成“裸 @”，回一句固定话术（已修）。

## 处理链路

```
attachment(url)
  → fetch（120s 超时）
  → 超过 20MB 只标“未下载”
  → saveMedia 落盘：<workspace>\.im-media\qq\<日期>\<时间戳>-<随机>.<ext>
  → extractFileText(path) 用 DSH 自带 Python 抽正文
  → 注入： [文件] 名称（ext，N 字，已解析）\n 正文前 4000 字
```

失败路径一律**不抛错**，只在同一行追加说明：

| 情况 | 注入内容 |
|---|---|
| 正常 | `[文件] AI日报.docx（.docx，5200 字，已解析）` + 正文前 4000 字 |
| 解析不出 | `（未能解析正文，只记文件名）` |
| 超 20MB | `（超过 20MB，未下载）` |
| 下载失败 | `（下载失败）` / `（下载出错）` |
| 未知格式 | 同上，只留文件名 |

## 支持的格式

| 格式 | 用什么抽 | 说明 |
|---|---|---|
| `.docx` | python-docx | 段落 + 表格（表格按行 `a \| b`） |
| `.xlsx` | openpyxl | 每个 sheet 加 `## 标题`，最多 200 行 |
| `.pptx` | python-pptx | 每个 slide 取文本框 |
| `.txt/.md/.csv/.json/.log` | 直接读 | UTF-8，读不出按 replace |
| `.pdf` | ❌ | 当前无解析库，降级为只记文件名 |

## 两个坑（都踩过）

1. **编码**：Windows 下 `python -c` 的 stdout 默认按 GBK 输出，Node 按 UTF-8 解码会全乱码。
   必须给子进程设 `PYTHONIOENCODING=utf-8` 和 `PYTHONUTF8=1`。
2. **空消息不等于裸 @**：文件消息 content 为空。空内容分支必须先判断
   `mentions[].is_you`（或内容里的 `<@botid>`），否则会对别人发的文件乱回话。

## 依赖

Python 与库来自 DSH 运行时，无需额外安装：

```
%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe
```

可用环境变量 `DSH_PYTHON_EXE` 覆盖。

## 限制

- 只解析**文本**，不解析图片里的字（表格截图另需 OCR）；
- 落盘文件沿用媒体保留策略（默认 7 天）——但正文已经进了会话/原文，不影响记忆；
- 一个文件最多注入 4000 字，长文档会被截断；
- 解析在进程内异步执行，超大文件（接近 20MB 的 docx）会让那条消息的回复慢几秒。

## 单测

```powershell
# 造样本（需要 python-docx / openpyxl）
python _make_sample.py
# 调插件里的 extractFileText
ELECTRON_RUN_AS_NODE=1 "E:\DeepSeek Harness\DeepSeek Harness.exe" test-docx.mjs
```

2026-11-22 实测：docx 52 字（标题/正文/表格齐全）、xlsx 28 字、未知 `.bin` 返回空串。
